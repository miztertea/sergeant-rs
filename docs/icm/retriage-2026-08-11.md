# Execution-surface re-triage — all 35 `.sergeant/workflows/` packages under §2a

Applied the hard intent test throughout: *would a human type `sgt run '<intent>' --workflow X`, and would different intents produce different runs?* Confirmation gates, precondition checks, and "read state → apply mechanically" checkpoints do **not** count as judgment under §2a bucket 2, even when the package's own ladder rung says §6.4 — several packages self-report §6.4 while the actual described behavior is a mechanical apply/cleanup/status operation.

## Per-package verdicts

**WORKFLOW (21)**
- `code-review` — WORKFLOW. Two isolated axes (Standards/Spec), each requiring real judgment on the diff's content; different diffs/spec sources produce different reviews.
- `cross-repo-work` — WORKFLOW. `20-define-dependency-order` breaks cycles via a named contract artifact — genuine cross-repo planning judgment, not mechanical.
- `deepen-module` — WORKFLOW. `10-design-it-twice` requires ≥3 independently generated designs compared on depth/locality — real alternative-weighing.
- `diagnose-bug` — WORKFLOW. `30-hypothesize` (3-5 ranked falsifiable hypotheses) and `10-build-feedback-loop`'s priority-order construction are textbook judgment; six stages survive proposal §8.2's reimplementation test per the package's own note.
- `direct-implementation` — WORKFLOW. Session-scoped implementation with explicit trigger ("user explicitly asks... one repo owns it"); delegates its gate to `validate-and-ship`.
- `dispatch` — WORKFLOW. `05-classify-risk` and `20-prepare-intent` require real routing/consent judgment; A4 already stripped its 12 extracted stages to the 5 that survive §6.3.
- `implement` — WORKFLOW. Explicit-invocation-only (BU-P2-051) — never auto-loaded; delegates to `tdd`/`code-review`.
- `prototype` — WORKFLOW. `00-select-branch` picks between logic/UI question types per the actual design question; different questions produce structurally different runs.
- `recover-stalled-worker` — WORKFLOW. `00-collect-signals` ("four signals collected together before any kill/relaunch decision") and the documented/undocumented stall-class distinction (`50-escalate-undocumented`) are diagnostic judgment, not applying an already-made decision — distinguishes it from `respond-to-worker` below.
- `repo-to-icm` — WORKFLOW. Ten-stage generator with real per-stage judgment (classification ladder, adversarial review); explicitly produces drafts only, never runnable procedure itself.
- `research` — WORKFLOW. "Primary sources only, every claim traced" — genuine investigative judgment per question; the dogfood run measured this as the one genuinely load-bearing artifact.
- `resolving-merge-conflicts` — WORKFLOW. `10-research-intent`/`20-resolve-hunks` require reading code semantics on both sides of a conflict and choosing a resolution with recorded trade-offs — not mechanical.
- `task-intake-and-route` — WORKFLOW. This **is** the intent-receiving front door: "any task the user brings," routes to direct-implementation or dispatch on 4 criteria. Canonical bucket-1 case.
- `tdd` — WORKFLOW. `00-agree-seams` requires user-confirmed seam judgment before any test is written.
- `to-spec` — WORKFLOW. `10-sketch-seams` ("fewest new seams at the highest possible seam") is design judgment.
- `to-tickets` — WORKFLOW. `10-extract-decisions-and-unknowns` requires distinguishing genuinely blocking unknowns from noise.
- `triage` — WORKFLOW. `30-recommend` produces a disposition proposal requiring evidence-weighing; non-linear transition graph explicitly preserved as fresh invocations, not engine control-flow.
- `validate-and-ship` — WORKFLOW. `40-drive-gates` ("ask-user findings relayed verbatim, never resolved autonomously") is the shipping-gate driver itself — irreducibly judgment-gated.
- `vet-external-skill` — WORKFLOW. Security-review judgment across 7 stages (source read, provenance, action audit, conflict check) — package text calls it "the smallest complete reference workflow in the corpus."
- `wayfinder` — WORKFLOW. `30-resolve-one` claims/resolves one ticket at a time with a loop back to `10-map-frontier` — genuine per-decision judgment. (Note: `00-name-destination` delegates to `grilling`, inheriting a partial E3 dependency for that sub-step only.)
- `worker-mission` — WORKFLOW. `10-triage-and-route` classifies into 5 categorically different disciplines (diagnose-bug/prototype/tdd/implement/deepen-module) — the definitional dispatched-worker contract.
