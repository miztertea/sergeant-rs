### contract:F1-fingerprint-collapses-distinct-questions — error

### contract:F2-w3-forced-race-has-no-hook — warning

**Claim.** W3's 'forced race' (§16.2) — landing a transition inside the watch client's own journal-head-read/stream-attach/work-read sequence — has no deterministic mechanism in this repo's current test infrastructure, which makes §17 acceptance criterion 9 effectively untestable as specified.

**Evidence.** This repo's precedented determinism primitives operate on the *daemon/backend* side only: `FakeStep::settle`/`settle_as` (src/backend/fake.rs:157-276) delay when an OBSERVE reveals a signal, and the `Gate` rendezvous (src/backend/fake.rs:290-333) pauses an in-process effect until an independent caller has proven it is parked. Live-daemon CLI tests (tests/m2_daemon_api.rs, tests/support/mod.rs's `DataDir`) instead spawn the real `sgt` binary and a real daemon as separate OS processes and talk to them over plain `reqwest`, with no IPC/env hook back into the CLI subprocess's internal step timing. `ApiClient` and `EventStream` are concrete structs (src/api.rs:2847-2851, 3029-3033), not traits, so there is also no mock seam for a module-level (§16.1) version of this test. Nothing in §13 (Proposed Implementation Shape) or §16 proposes a test-only synchronization point inside the not-yet-written watch loop.
