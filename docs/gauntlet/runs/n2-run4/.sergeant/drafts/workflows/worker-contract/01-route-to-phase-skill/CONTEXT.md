# 01-route-to-phase-skill

## Inputs

| File | Layer | Why |
|---|---|---|
| ../CONTEXT.md | L1 | workflow orientation (first stage only) |

## Purpose

**Trigger:** a worker begins a phase of implementation work

**Outcome:** the worker's approach is selected by a fixed routing table matching work shape to skill, rather than improvised per worker

**Statement (the operative rule):** Before implementation, a worker routes to the canonical engineering skill matching the phase of work — huge/foggy work surfaces wayfinder/to-spec/to-tickets as escalation rather than being silently executed as implementation, hard bugs load diagnosing-bugs, uncertain logic/UI loads prototype (never promoting prototype code directly), approved implementation loads tdd, and merge/rebase conflicts load resolving-merge-conflicts (never aborting automatically).

## What must become true here (durable outcome)

The worker's approach is selected by a fixed routing table matching work shape to skill, rather than improvised per worker — per the Statement above, which is the operative rule this stage exists to enforce.
