# M4 Contract — Native Backends, Recovery, Regression Catalog

**Outcome.** The backend trait meets reality: a Claude adapter drives the
installed Claude Code CLI through real executions with durable session
identity, raw + normalized trajectory capture, model-pin verification, and
restart reconciliation; a Codex adapter implements the App Server protocol
behind opt-in contract tests; and Sergeant's failure catalog becomes
regression tests. Every adapter claim is **measured against the installed
binary, never assumed from documentation** (LESSONS L1) — contract tests
gate the CLI versions we trust.

**In scope** (proposal §15 full contract, §16, §17, §20, §25, §27, §37;
deviation D2; LESSONS L1/L2; the measured spike in
`reference/sergeant-upstream/docs/research/claude-background-harness-spike.md`).

- `backend/mod.rs` — extend the trait to the full §15 shape as evidence
  demands: add `interrupt`, `resume`, `history`; `subscribe` only if the
  Claude adapter's streaming genuinely needs a push surface beyond
  per-turn stdout ingestion (R1 otherwise). Capabilities stay honest:
  unsupported means unsupported.
- `backend/claude.rs` — per D2's leading candidate: **headless print-mode
  turns over a durable session**. `claude -p --verbose --output-format
  stream-json`, prompt via stdin, `--resume <session_id>` for every later
  turn (never `--fork-session`); `--setting-sources user` so the target
  repo's project memory cannot capture the execution agent (the no-mistakes
  hazard, LESSONS L2); permission mode per profile with the root/
  `IS_SANDBOX` constraint documented. Execution = durable conversation
  (session_id); the per-turn process is not the execution (§25's separation,
  natively). Interrupt = terminate the per-turn process; the conversation
  survives; resume continues it. Raw stream-json lines archived via the M1
  blob store (§20); normalized `conversation.*`/`tool.*`/`usage.*` events
  journaled (§27).
- **Model-pin verification, three layers** (adapted from the spike to print
  mode): pre-flight shape check (bare alias or full ID — provider-qualified
  fails closed before launch); launch-failure detection from the result
  envelope; substitution detection from the result's model fields (the
  spike proved exit codes and mission success are never sufficient). A pin
  is "honored" only with positive evidence, else recorded as attempted.
- **Capability/version probe:** `claude --version` + probe of required
  flags recorded at backend registration; contract tests define the minimum
  trusted version (installed here: 2.1.226; the spike measured 2.1.220 —
  differences are findings, not surprises).
- `backend/codex.rs` — App Server JSON-RPC per §16's mapping (thread =
  execution, turn/start, turn/interrupt, thread/read history, notifications
  as events). Built to the documented protocol; **all Codex tests opt-in**
  (`#[ignore]`d with a doc comment) since Codex is not installed here — the
  adapter compiles and its protocol layer is unit-tested against recorded
  fixtures, nothing more is claimed.
- Recovery (§25 with real processes): daemon restart reconciles Claude
  executions via session existence/liveness evidence (`claude -p --resume`
  probe or session listing — measure which is reliable); ambiguity fails
  closed to `blocked` with evidence; the fake backend keeps covering the
  deterministic matrix.
- **Regression catalog** (§37, from `reference/sergeant-upstream`): as tests
  against the fake backend where deterministic, against Claude where cheap:
  worker-reports-done-but-native-session-alive; daemon dies during delivery;
  native dies after work preserved; duplicate command delivery; stale
  execution identity reused; client disconnects mid-run; work waits hours
  (no timeout-kills state). Each catalog entry cites its Sergeant origin.
- Real-Claude tests: **opt-in via env var** (`SERGEANT_CLAUDE_TESTS=1`),
  budget-conscious (smallest model, one-line prompts, few turns), skipped
  cleanly when unset or unauthenticated. CI runs them never; this container
  can run them once per gauntlet round at most.

**Acceptance tests.**

1. Contract test (opt-in, real Claude): start → session_id captured; second
   `send` resumes the same session_id (continuity proven by the
   conversation, e.g. recall of a nonce from turn 1); raw lines in blob
   store; normalized events journaled with correlation/causation.
2. Model pin: valid alias honored (result model field matches); provider-
   qualified rejected pre-flight; substitution path unit-tested against a
   recorded fixture of the substitution envelope (not live — we cannot
   force entitlement failures on demand).
3. Interrupt: mid-turn process termination leaves work state untouched
   (work ≠ process), conversation resumable after (opt-in, real).
4. Recovery: daemon restart with a recorded Claude execution reconciles
   from evidence; a session that no longer exists → execution retired,
   work `blocked` with evidence, never silently failed (L6 class: check
   the multi-append windows in start/reconcile).
5. Codex: protocol layer round-trips recorded JSON-RPC fixtures; all live
   tests `#[ignore]`d.
6. Regression catalog: every listed Sergeant failure has a named test
   citing its origin, green against the fake backend.
7. Version gate: adapter refuses (fail closed, structured error naming the
   probe) when required CLI capabilities are absent.

**Non-goals.** OpenCode/Prime adapters (§38 defers them); tmux anything;
credential storage (§14 — profiles reference native auth only); driving
Claude's interactive TUI or `--bg` supervisor (fallback only if print-mode
turns are measured inadequate — that measurement, not preference, reopens
D2); DuckDB/OTel (M5); TUI/HTML (M6).

**Unknowns.**

- Whether `--resume` works reliably across daemon restarts and from a
  different cwd than the session's origin — measure early; the adapter's
  recovery story depends on it.
- Long-turn behavior of print mode (streaming cadence, timeout handling,
  what a killed turn leaves in the session file) — measure.
- Whether concurrent print-mode sessions in one worktree interfere —
  measure before allowing parallel executions per surface.
- The substitution-warning surface in print mode (transcript line vs result
  envelope field) — the spike measured the TUI; print mode may differ.
- Cost/limit behavior: a turn that dies on a usage limit must surface as a
  structured execution failure, not ambiguity (we have empirical experience
  with this failure mode from this very project).

**Dependency budget.** None expected: process driving via std/tokio process
(already in tree), JSON via serde_json. Anything else, rung-logged.

**Gauntlet depth.** Economy cadence. Builder on **Fable high** (the one
milestone pre-authorized for it — adapter/recovery core, D2's resolution
lives here). Invariants critic Fable high; others Opus medium; batched
refuters; checkpoint gate; lean round 2. All prompts carry: register-first,
probe hygiene, exploration budget, rung logging, and L6/L7 (check
multi-append windows; every fix ships its pinning test).
