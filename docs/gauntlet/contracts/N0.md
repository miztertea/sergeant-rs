# N0 — Runtime-Remediation Adjudication (Next Iteration kickoff)

Governing document: `reference/proposal-next-iteration-icm-workflows.md`
(§21.1), the successor/addendum to
`reference/proposal-depot-rust-execution-surface.md`. The successor proposal
was audited against `27c00ef` and accepted by the owner on 2026-08-10 with the
amendment recorded in ruling R-N0-3 below.

## Outcome

Every P1-PERF and Bug Sprint finding that intersects executor expansion is
either fixed-and-pinned, or explicitly ruled/deferred with a named trigger.
N0 is adjudication, not implementation: no code changes. Its product is this
contract, the ledger entry, and the budgets N3/N4 are held to.

## Rulings

Each ruling names its Ponytail rung and its trigger. Rulings are findings too
(L9): they are reviewable by any later panel against this record.

### R-N0-1 — #14 / B3 (stop/join under the core lock): prerequisite, resolved inside N3

The §15 trait revision is B3's registered trigger, and N3 *is* that revision.
The two-phase external-effect boundary (proposal §14.2) — `execution.reserved`
under the lock, external start/wait outside it, verified result append back
under it — subsumes the narrower "stop returns a join token" fix. Fixing #14
separately in N0 would build a seam N3 immediately rebuilds (R1: don't build
it twice). **Trigger fired: N3's contract must list #14/B3 closure in its
acceptance criteria, with the §22.6 lock-discipline instrumentation tests.**

### R-N0-2 — #20 (systematic crash-point injection): folded into N3/N4 gates

The proposal's §22.5 injection matrix (eight windows per external lifecycle)
is #20 made systematic. A standalone injection sprint before N3 would probe
the *current* single-phase seam, which N3 replaces (R1). **Trigger: N3 and N4
gates each require the §22.5 matrix over their lifecycles; #20 closes when
both land.** L6 remains binding on any interim journal-touching change.

### R-N0-3 — #17 (retention/GC) + #4 (unbounded terminal-work RSS): deferred with hard triggers — the owner-accepted amendment

The proposal defers retention to "existing backlog work" (§23) without naming
when that debt comes due. The accepted amendment makes it explicit:

- **Phase A (N1/N2) does not fire the trigger.** Content work adds ordinary
  Git files; a repo-to-icm run is tens of works (~25 kB RSS and ~16 events
  each at baseline), not thousands. No retention work is required to start.
- **#17 trigger: the N4 contract may not be written without a retention
  design ruling.** Execute stages stream arbitrarily large logs into the blob
  store (§16.9 caps the *journal* cost, not the *disk* cost). Before N4
  ships, a design contract must rule on blob retention for terminal works'
  raw evidence and journal segment archival — even if the ruling is "measured
  budget X, GC deferred again with trigger Y." Silence is no longer a legal
  state for #17.
- **#4 trigger: fires with #17's (N4 contract time), or earlier if any
  measured session exceeds 150 MB retained RSS** (~5× the 50-work baseline).
  The eviction design should ride the same contract as #17 — both are
  "terminal work still occupies a live resource" defects (R2: one design,
  two resources).

### R-N0-4 — #6 / #7 / #10 (throughput plateau, graph queueing, cold-query scaling): budgets, not blockers

These are measured characteristics of a healthy architecture under its
documented single-writer invariant, not defects blocking Phase A. They become
**regression budgets** for Program B, from `docs/perf/baseline-2026-08-10.md`:

| Budget | Line | Bound |
|---|---|---|
| Submission throughput | S1 plateau | ≥ 28 works/s at burst 50 |
| Single-submit e2e p50 | S1 b1 | ≤ 50 ms |
| Core-lock discipline | new (N3) | no external I/O, process wait, or thread join under the core lock (§22.6 tests) |
| Execute-capture memory | §22.8 | peak RSS increment ≤ 64 MiB during a 1 GiB log capture |
| Rebuild rate | S5 | ≥ 15k events/s at 50k events |
| Journal cost per execute stage | §16.9 | O(1) events per stage regardless of log lines |

Re-measure #7/#10 after N3 lands; the two-phase boundary is expected to
improve read queueing under stalled executors, and that expectation is a
claim to verify, not assume.

### R-N0-5 — #18 (/proc portability): deferred to N5 (proposal placement confirmed)

Recovery-evidence portability matters when a non-Linux platform is qualified,
and N5 is where qualification lives. The recovery ladder in proposal §18.4
(native identity first, process scan as supplementary evidence only) is
adopted as the design rule now so N3's trait revision doesn't bake in a
`/proc` dependency for new seams. **Trigger: N5 contract.**

### R-N0-6 — #19 (real-Claude soak): narrowed into the N2 gate

The installed CLI is 2.1.226 and `MIN_TRUSTED_VERSION` is already
`(2, 1, 226)` — M4 re-measured on exactly this version, so no re-measurement
gap exists. Owner ruling 2026-08-10: 2.1.226 is the measured floor; older
versions are unmeasured and remain refused by the probe (the code's existing
posture — L1). A dedicated synthetic soak is redundant with N2, whose
repo-to-icm run against real Claude *is* a multi-stage, multi-hour soak with
a complete trajectory. **Trigger: #19 closes when N2's real-Claude
measurement run completes with its evidence attached; a fake-backend N2 run
alone does not close it.**
