# M1 Contract — Event Core

**Outcome.** The durable-trajectory core as library code with tests: an event
envelope, an append-only segmented JSONL journal with crash recovery, a
content-addressed blob store, and reducer-based in-memory projection with
snapshot + replay. This is the layer every later milestone writes through; it
must be boring and provably correct before anything sits on it.

**In scope** (proposal §18–§21, §24; testing per §37 "deterministic core").

- `domain/event.rs` — envelope per §19, adapted per deviation D1: `schema:
  "sergeant.event/v1"`, ULID `id`, daemon-local monotonically increasing `seq`
  (u64), RFC3339 `timestamp`, `source {type, name}`, optional
  `workspace_id`/`work_id`/`execution_id`, `correlation_id`, `causation_id`,
  `kind` (dotted string), `payload` (JSON). Serde round-trip stable. Unknown
  fields in stored events are preserved on read (forward compatibility — §20's
  "future versions reinterpret history").
- `runtime/journal.rs` — append-only segmented NDJSON under a caller-supplied
  data dir (`journal/00000001.ndjson`, …). Single-writer type; one complete
  event per line; fsync on append (durability before acknowledgment); size-based
  segment rotation; a trailing incomplete line after crash is detected on open
  and recovered (quarantined or truncated) without losing any complete line;
  replay iterator yields all events in seq order across segments; append assigns
  the next seq and rejects regressions.
- `runtime/blob.rs` (or inside journal module if smaller) — content-addressed
  store `blobs/b3/<blake3-hex>`; `put(bytes) -> BlobRef`, `get(&BlobRef)`;
  write-once semantics; events carry `blob_ref` strings (`"b3:<hex>"`).
- `runtime/projection.rs` — `Reducer` as pure `fn(&mut State, &Event)`;
  a `Projection` that folds the journal; snapshot write/load (snapshot is an
  optimization, never canonical — §24); restart path = load snapshot + replay
  tail, provably identical to full replay. One concrete projection now:
  per-kind event counts, last seq, and the set of distinct `work_id`s seen —
  enough to prove determinism without inventing domain semantics early.

**Acceptance tests** (all in `cargo test`):

1. Round-trip: envelope serializes/deserializes losslessly; unknown fields
   survive a read-modify-write of the projection (not of the stored line —
   stored lines are immutable).
2. Crash tail: a journal whose last line is truncated mid-JSON opens cleanly,
   recovers every complete event, and the next append continues the seq.
3. Rotation: appends past the segment threshold create a new segment; replay
   spans segments in order.
4. Determinism: full replay twice → identical projection state; snapshot at
   arbitrary seq + tail replay → identical to full replay.
5. Seq integrity: replay detects a gap or duplicate seq and fails closed
   (error, not silent skip).
6. Blob: put/get round-trips; identical content deduplicates to one file;
   hash mismatch on read fails closed.

**Non-goals.** No daemon, no HTTP, no domain state machines (Work states arrive
in M2), no DuckDB, no OTel, no async I/O cleverness — plain std fs I/O behind
the single-writer type is fine at this scale (Ponytail).

**Unknowns.**

- fsync guarantees on the CI/container filesystem are unverifiable from inside
  the process; the test asserts our fsync calls happen (and crash-tail recovery
  covers the failure half), not OS-level durability.
- Snapshot format versioning: simplest thing — a `schema` field and refuse
  unknown versions (fail closed to full replay, which is always available).

**Gauntlet depth.** Full four-axis panel (spec-fidelity, invariants, simplicity,
test-honesty), Fable on invariants — this is the milestone the one-owner and
durable-trajectory principles stand on.
