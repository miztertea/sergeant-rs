# N3 — Executor-Aware Stage Model + Two-Phase External-Effect Boundary

Governing: proposal §§11–14, §21.4, §22.3–22.6; N0 rulings R-N0-1/2/4
(budgets binding); N2 grammar-pressure report (GP-2 licenses the ask
primitive; nothing else licenses new machinery).

## Outcome (issue ownership: closes #14, #20, #42)

1. **Two-phase external-effect boundary** (§14.2): under the core lock —
   validate, allocate execution id, pin executor spec, append
   `execution.reserved`, return an effect request; outside the lock —
   reserve/create native identity, launch, observe; back under the lock —
   verify id+attempt still current, append observed events, transition.
   Closes the Claude start-window (§14.3: prepare→journal→launch) and
   **#14/B3** (stop/interrupt expose join handles awaited outside the
   guard; B3's registered trigger fires here).
2. **Tagged stage definitions** (§12, backward-compatible): legacy
   workflows parse identically; `[stage."<id>"]` tables add `kind =
   "actor"`, per-stage `harness`/`profile`; unknown kinds and misplaced
   fields fail closed; full executor spec pinned in `workflow.bound`;
   workflow content identity over execution-relevant fields.
3. **Per-stage actor selection** (§12.5): stage harness explicit → else
   Work actor default via today's routing chain → else fail with options.
   No silent substitution, stage by stage. Whole-workflow capability
   preflight rejects before Work/worktree side effects (§17.5). Proven
   with two registered fake harness identities.
4. **GP-2 / #42 — actor-initiated ask**: a backend signal pathway by which
   a live execution parks its stage in `needs_input` on a question the
   actor authored, resumable by today's `respond` (same execution, per the
   measured U1 semantics). Implemented for fake (contract-tested) and
   Claude (measured against 2.1.226's stream affordances; capability flag
   + contract test per L8; unmeasurable → flag stays false, fail closed).
5. **#20 closed**: the §22.5 crash-injection matrix (all eight windows)
   over the new reservation lifecycle, per L6.

## Budgets (R-N0-4, measured against `docs/perf/baseline-2026-08-10.md`)

Throughput ≥28 works/s at burst 50; single-submit p50 ≤50 ms; **no
external I/O, process wait, or thread join under the core lock** (§22.6
instrumentation: a deliberately stalled fake executor must not block
independent requests beyond the journal commit interval); rebuild ≥15k
ev/s at 50k.

## Non-goals

No Docker (N4), no container runtime trait, no native command stage, no
composition, no model-per-stage (profile carries model, §24.8), no
retention work (N4's contract owns the R-N0-3 ruling).

## Amendment — adjudication A-N3-1 (2026-08-10, budget breach ruling)

Wave-1 measurement (`docs/perf/n3-two-phase-boundary-2026-08-10.md`): the
two-phase boundary breaches the burst-50 floor — 24.5 works/s vs ≥28 — via
+2 fsynced events/work; same-machine control 33.0/s, so the true cost is
~25%. The builder's refusal to merge `stage.entered`+`execution.reserved`
is UPHELD: §22.5 enumerates that append's two sides as distinct injection
windows and tests pin them; throughput bought by deleting a crash window is
not a legal trade. Ruling: the budget is amended for this milestone to
**≥24 works/s at burst 50 with the control-measured delta documented**, and
the principled fix — journal group commit, one fsync per lock hold — is
filed as **#44 with a hard trigger: lands before the N4 contract ships**
(Docker adds reserved-event volume). Per L9 this ruling is panel-reviewable;
the wave-1 critics grade it with the rest of the tree.
