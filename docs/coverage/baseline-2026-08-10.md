
scope, `#[cfg(test)]` inclusion, stale-profdata hazard, signal semantics,
…) live in `scripts/coverage/README.md`. The two `#[ignore]`d real-Claude
tests are never run (R-N0-6). Run the stages via
`scripts/coverage/c0-show-env.sh` … `c4-report.sh`, strictly in order.

**The inflation caveat, stated before any use of these numbers:**
`#[cfg(test)]` code inside `src/` is included and counts as covered —
measured, not assumed (harness README claim 5). 3,396 of 18,861 `src/`
lines (18.0%) sit under a `#[cfg(test)]` marker (tui.rs 41%, fsutil.rs
49%, recovery.rs 47%, router.rs 41%, surface.rs 39%). The honest
product-code coverage is therefore lower than the headline; stable Rust
offers no exclusion that does not edit `src/`. Any future gate number is a
gate on *this* convention's number, nothing more.

  profiles, zero lost; every stage's accounting balanced
  (produced=mergeable, discarded=0, lost=0). The loss sites §6.1 predicted
  did not recur.

  against the stand-in CLI. The live-path-only regions (the paths only the
  two `#[ignore]` tests reach: real version-gate probing and live envelope

  input per R-N0-6, not filed here.
- **Static-scan tests** (m6 t5 family, SSE vocabulary, stack pins)
  execute near-zero product lines by design; their protection is structural,
  not line-covering.

  cannot execute on this container (issue #18's subject, not a gap).
- **Instrument artifacts** (refuter-documented, in the workflow record):
  Debug impls required by derive chains; line-layout artifacts where a
  wrapped `?` puts an untaken error region on its own line while the
  identical one-line propagation reads as covered.
